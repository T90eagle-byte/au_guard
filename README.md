
# au_guard

**Модульный конвейер обработки событий безопасности на Go**

Учебный проект по дисциплине «Специализированные языки и технологии программирования», развиваемый в ходе лабораторных работ №2–7.

Проект демонстрирует построение тестируемого CLI-приложения, потоковую обработку JSONL, ограниченный конкурентный конвейер, корректную остановку и безопасную работу с файловыми артефактами.

**Технологии:** Go 1.26.7 · ALT Linux · JSONL · Goroutines · Context · os.Root · Git

## Возможности

- Строгая валидация событий безопасности и конфигурации.
- Потоковый ввод JSONL из файла или стандартного ввода.
- Формирование JSONL-решений по уровню серьёзности события.
- Конкурентная обработка с ограничением числа workers и очереди.
- Backpressure и сохранение исходного порядка результатов.
- Обработка отмены контекста, SIGINT и SIGTERM.
- Безопасное чтение файлов внутри доверенного каталога через `os.Root`.
- Атомарная публикация JSON-отчётов.
- Вычисление SHA-256 средствами Go и внешней утилитой `/usr/bin/sha256sum`.
- Автоматические тесты, негативные эксперименты и Race Detector.

> Инструменты `read_artifact` и `hash_artifact` реализованы как программные компоненты и проверяются локальными тестами. Они не запускаются автоматически из входных JSONL-событий команды `ingest`.

## Быстрый старт

### Требования

- Linux, рекомендуемая среда — ALT Workstation 11.2 (p11).
- Go 1.26.7; проверочный сценарий использует точную версию из `toolchain.txt`.
- Git.
- GCC и CGO для Race Detector.
- `/usr/bin/sha256sum` для испытаний ЛР7.

### Запуск

```bash
git clone https://github.com/T90eagle-byte/au_guard.git
cd au_guard

go run ./cmd/au-guard ingest --input testdata/events.jsonl
```

Пример результата в stdout:

```json
{"event_id":"demo_1","action":"observe","reason":"low_severity"}
{"event_id":"demo_2","action":"review","reason":"high_severity"}
```

Служебная статистика и диагностика выводятся отдельно в stderr.

Пример с настройкой конкурентности:

```bash
go run ./cmd/au-guard ingest \
  --input testdata/events.jsonl \
  --workers 4 \
  --queue 8 \
  --timeout 5s
```

Для чтения из stdin:

```bash
go run ./cmd/au-guard ingest --input - < testdata/events.jsonl
```

## Тестирование

Обычные тесты:

```bash
go test -count=1 ./...
```

Поиск гонок данных:

```bash
CGO_ENABLED=1 go test -race ./...
```

Статический анализ:

```bash
go vet ./...
```

Полная проверка проекта:

```bash
bash scripts/check.sh
```

Проверочный сценарий контролирует версию Go, форматирование, тестирование и сборку. На стенде с другой версией toolchain он может завершиться ошибкой проверки среды.

Подробнее: [тестирование и воспроизводимость](docs/testing.md).

## Архитектура

```text
au_guard/
├── cmd/au-guard/       # точка входа и управление завершением
├── internal/
│   ├── cli/            # интерфейс командной строки
│   ├── config/         # параметры и границы конфигурации
│   ├── events/         # модели Event и Decision
│   ├── pipeline/       # источники, обработчики, worker pool
│   ├── providers/      # тестовая реализация Model
│   └── tools/          # файловые инструменты и SHA-256

├── evidence/           # результаты проверок лабораторных
├── scripts/check.sh    # единый сценарий проверки
└── go.mod
```

## Ограничения

Проект предназначен для учебных экспериментов, а не для промышленной эксплуатации.

В частности, `os.Root` не заменяет системную песочницу, Race Detector проверяет только фактически исполненные пути, а отмена контекста требует корректного взаимодействия с блокирующими операциями ввода-вывода.
