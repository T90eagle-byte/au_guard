# Лабораторная работа 8: HTTP API

Сервер принимает запросы только на адресе `127.0.0.1`. Аутентификация и постоянное хранилище в этой работе отсутствуют: сервер предназначен для учебного стенда, а не для рабочих данных.

Запуск из корня проекта:

```bash
go run ./cmd/au-guard serve --addr 127.0.0.1:8080
```

Ограничение частоты общее для процесса: по умолчанию допускается 100 запросов за одну секунду. Параметры можно изменить, например `--rate-limit 3 --rate-window 10s`. После исчерпания лимита сервер возвращает 429 с кодом `rate_limited`; в начале следующего интервала запросы снова допускаются. Это ограничение учебного стенда, а не полноценная защита от распределённой атаки.

Маршруты:

- `GET /healthz` проверяет работу HTTP-процесса.
- `GET /readyz` вызывает проверку инициализированного прикладного ядра с тайм-аутом 500 мс.
- `POST /v1/events` принимает один JSON-объект размером не более 1 MiB и возвращает решение существующего обработчика правил.

Пример запроса:

```bash
curl -i -H 'Content-Type: application/json' \
  --data '{"id":"evt-001","kind":"auth","severity":2,"message":"login denied"}' \
  http://127.0.0.1:8080/v1/events
```

Ответы возвращаются в JSON. Сервер создаёт новый `X-Request-ID` для каждого запроса и записывает в структурированный журнал только идентификатор, известный маршрут, статус и длительность. При SIGINT или SIGTERM входящие операции получают отмену контекста, а ожидание остановки ограничено пятью секундами.

Проверки выполняются командами `go test ./...`, `go vet ./...`, `go test -race ./...` и `bash scripts/check.sh`.
